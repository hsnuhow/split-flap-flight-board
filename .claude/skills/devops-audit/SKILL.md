# /devops-audit

你（主控）派 `devops-auditor` 平行稽核，彙整成一份報告。

維度分兩組，**標尺不同**：

- **維度 1–6 合規與正確性**——問「有沒有、對不對」，用 HIGH／MEDIUM／LOW
- **維度 7–9 最佳化**——問「配得好不好」，用「效益 × 施作成本」

把「記憶體超配一倍」跟「沒有備份」放同一個尺標會失真，所以分開。

**全程唯讀。** 稽核不修東西——發現問題出報告，修不修、怎麼修由使用者決定。
主控也不得在稽核流程中順手修。

## 第一步：取得判準

**判準不在本檔案裡。** 開始前先取得最新標準：

```bash
# 本機已有 clone（一般情況）
git -C ~/MyDeveloper/OpDev pull --quiet && cat ~/MyDeveloper/OpDev/standards/AUDIT.md

# 本機沒有 clone（雲端 session、另一台機器）
git clone --depth 1 --quiet https://github.com/hsnuhow/OpDev.git /tmp/opdev-standards
cat /tmp/opdev-standards/standards/AUDIT.md
```

OpDev 是**私有 repo**，所以 `raw.githubusercontent.com` 會回 404。
用 git 而不是 HTTP：走既有的 credential helper、不必處理 token、
而且一次就拿到所有標準文件（`AUDIT.md` 會指向其他幾份）。

`AUDIT.md` 第一節列出九個維度各自的判準來源，依需要一併讀取。

**取不到就停下來回報，不要憑印象稽核。**
憑印象會產生看起來合理但實際過期的結論——一個過期的「通過」會被當成
「已經檢查過了」的證據，那比沒有稽核更危險。

`git pull` 失敗但本機有舊副本時：**可以繼續，但必須在報告開頭註明
「判準版本：本機副本，未能同步」**，讓讀報告的人知道結論可能基於舊標準。

## 第二步：讀專案自己的設定

- `CLAUDE.md` 最前面的部署口令與上線流程：本專案是雙軌還是單軌、對應的雲端專案 id
- `CLAUDE.md` 裡有沒有**例外宣告**（宣告過的例外判為通過，不是缺陷）
- 若有 `check-env.md`，讀它——那裡記著上次稽核的已知問題

資訊不齊就先問使用者，不要開始。

## 第三步：派工

**同一回合並行派出** `devops-auditor`，各給一個維度（定義見 `AUDIT.md` 第一節）。

預設派 1–6（合規）。使用者要求最佳化時再加派 7–9。
**九個一起派會產出過長的報告**，多數情況下使用者只想知道其中一組。

每個派工都要明確寫出：**專案路徑、雲端專案 id、單軌或雙軌、以及唯讀禁令**。

## 第四步：彙整

收齊後合併，**不要只是把六份報告貼在一起**：

1. **去重**：同一個根因在多個維度出現時合併成一項
2. **重排序**：跨維度依實際風險排序，不是依維度順序
3. **標出因果鏈**：獨立看是 MEDIUM、串起來是 HIGH 的組合要點出
   （例：「單軌 ＋ 有真實使用者 ＋ 無備份 ＋ 無還原口令」＝ 事故時無法復原）

## 報告格式

```
# DevOps 稽核 — <專案> — <日期>
判準版本：<線上 / 本機 fallback>

## 一句話結論
<最該處理的一件事>

## HIGH
每項：發現 / 證據（指令與輸出）/ 為什麼危險 / 具體處置

## MEDIUM
## LOW

## 最佳化建議（若有派 7-9）
每項：現況（附指令與輸出）/ 建議 / 效益（量化）/ 施作成本
**估不出效益的不要列**——沒有數字的建議使用者無從判斷，整區會被略過
## 通過（簡列，證明真的查過）
## 無法驗證
<項目與原因。空的也要寫「無」。>

## 建議順序
<若時間有限，先做哪三件>
```

不使用 emoji。

## 用法

- `/devops-audit` — 合規稽核（維度 1–6）
- `/devops-audit 最佳化` — 只查最佳化（維度 7–9：部署配置、權限最小化、費用）
- `/devops-audit 全部` — 九個維度都跑
- `/devops-audit 部署` — 只查部署口令與流程（上線前快檢）
- `/devops-audit 費用` — 只查費用最佳化

## 與 OpDev 的分工

| 工具 | 範圍 | 頻率 |
|---|---|---|
| `/devops-audit` | **單一專案**深度稽核，含文件與程式碼 | 上線前、接手時、每季 |
| `check-env.md` | 單一專案的一次性檢查清單 | 一次 |
| `opdev scan --plan` | **跨全部專案**的雲端掃描 | 每週 |
| `opdev health` | 跨專案的服務健康 | 每日 |

`/devops-audit` 查得比 `opdev` 深（會讀文件、跑測試），但只看一個專案。互補，不互相取代。
